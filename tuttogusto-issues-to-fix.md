# Технический аудит прототипа Tuttogusto — задачи на исправление

Промпт для ИИ: проанализируй текущий проект (Next.js) по каждому пункту ниже, найди причину в коде и предложи/внеси исправление. По каждому пункту сначала объясни, в чём именно проблема в данном конкретном проекте, затем исправь.

## 1. Рендеринг каталога (`/menu`) — вероятно CSR вместо SSR/SSG
**Проблема:** при первой загрузке страницы `/menu` в HTML-ответе сервера отсутствуют сами товары — виден только текст-заглушка вида "Загружаем меню...". Это указывает, что список товаров подгружается уже в браузере через клиентский `fetch`/`useEffect`, а не приходит сразу в HTML с сервера.

**Почему это плохо:**
- Поисковые роботы (Google, Яндекс) могут не увидеть содержимое каталога при индексации — карточки блюд не проиндексируются, страница не будет ранжироваться по запросам вроде "паста Иркутск доставка".
- Пользователь с медленным интернетом или на слабом телефоне видит пустой экран/спиннер дольше, чем нужно — это ощущается как "тормозит сайт".

**Что нужно сделать:**
- Проверить, какой механизм получения данных используется на `/menu` (`use client` + `useEffect` + `fetch`, или серверный компонент).
- Перевести получение списка товаров на серверный рендеринг: Server Component с прямым запросом к БД/API, либо `generateStaticParams` + ISR (`revalidate`), если меню меняется не каждую секунду.
- Проверить, что после исправления во View Source (или через `curl`) в HTML-ответе реально видны названия и цены блюд, а не только скелет разметки.

## 2. Дублирование карточек товаров в блоке "Рекомендуем"
**Проблема:** в HTML главной страницы одни и те же карточки товаров (например, "Завтрак Вода", "Крем-суп из брокколи" и т.д.) повторяются подряд более десяти раз одним и тем же набором.

**Что проверить:**
- Если это сделано специально для бесконечной/зацикленной карусели (дублирование DOM-элементов ради бесшовной прокрутки) — это нормальная техника, но нужно убедиться, что дублирующиеся карточки помечены как декоративные для скринридеров и поисковиков (`aria-hidden="true"` на дублирующихся копиях, оригинал остаётся доступным).
- Если это не карусель, а баг рендера (например, массив товаров случайно замэплен несколько раз, или неправильно указан `key` в `.map()` вызывающий лишние ре-рендеры) — нужно найти источник и убрать дублирование, оставив каждую карточку один раз.

## 3. SEO и метаданные
**Проблема:** нужно проверить полноту SEO-настроек для многостраничного каталога, а не только для главной.

**Что нужно сделать:**
- Убедиться, что у `/menu` и у каждой карточки товара (если есть отдельные страницы товаров) есть уникальные `title` и `meta description`, а не только у главной страницы.
- Добавить `Open Graph`/`Twitter Card` метатеги с фото блюда для расшаривания ссылок в мессенджерах.
- Добавить структурированные данные Schema.org типа `Restaurant`/`Menu`/`Product` (JSON-LD), чтобы поисковики понимали цены и меню.
- Сгенерировать `sitemap.xml` и `robots.txt`, если их ещё нет.
- Проверить семантику заголовков (`h1` только один на страницу, логичная вложенность `h2`/`h3`).

## 4. Производительность и загрузка
**Что нужно проверить:**
- Все ли изображения товаров идут через `next/image` с корректными `width`/`height`, чтобы не было сдвига層 layout (CLS).
- Задать `priority` только для изображений в первом экране (hero-баннер), остальные должны лениво подгружаться.
- Прогнать Lighthouse (вкладка DevTools → Lighthouse) по `/`, `/menu`, `/cart` и зафиксировать текущие баллы Performance/SEO/Accessibility/Best Practices — затем повторить после исправлений для сравнения.

## 5. Корзина и состояние заказа
**Что нужно проверить:**
- Синхронизируется ли состояние корзины между вкладками/перезагрузкой страницы (через `localStorage`), либо оно сбрасывается при обновлении.
- Обрабатываются ли граничные случаи: добавление товара, которого не существует, отрицательное количество, пустая корзина при переходе на `/cart`.
- Есть ли понятная обратная связь пользователю при добавлении товара в корзину (визуальное подтверждение, а не просто смена счётчика в шапке).

## 6. Адаптивность и доступность
**Что нужно проверить:**
- Корректность вёрстки на узких экранах (320–375px) — особенно карусель категорий и сетка карточек меню.
- Наличие `alt`-текста у всех изображений блюд (не пустой, с описанием блюда, а не просто "image").
- Достаточный контраст текста на фоне фотографий в hero-блоке.

## 7. Админ-панель (если уже реализована)
**Что нужно проверить:**
- Реально ли редактирование через `/admin` отражается на `/menu`, или каталог всё ещё частично на моковых/захардкоженных данных.
- Есть ли базовая защита доступа к `/admin` (аутентификация), чтобы посторонний не мог зайти и изменить меню.
